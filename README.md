# MagmPaper

Приложение для персонализации **Windows 11 x64**: живые GLSL-обои и настройка панели задач. Добавляйте фрагментные шейдеры с glslsandbox.com, сохраняйте их в коллекцию и устанавливайте на основной монитор. Есть встроенный пример, предпросмотр, редактирование, удаление, остановка и значок в трее.

## Установка и запуск

Скачайте **MagmPaper-Setup-0.3.0.exe** из [релиза 0.3.0](https://github.com/Magmanitos/MagmPaperEngine/releases/tag/v0.3.0), полностью закройте прежнюю версию через трей → «Выход» и запустите установщик.

- По умолчанию программа устанавливается для текущего пользователя в `%LOCALAPPDATA%\Programs\MagmPaper`. Папку можно выбрать в мастере установки.
- Компоненты приложения, включая Electron и нативные модули Windows, включены в установщик. Собственный модуль оформления стандартной панели задач также входит в комплект; Windhawk не нужен. Устанавливать Node.js, npm или VS Code не требуется. Интернет во время установки не нужен.
- Запускайте **MagmPaper** через ярлык на рабочем столе или в меню «Пуск».
- GLSL-файлы находятся в `%APPDATA%\MagmPaper\Wallpapers`, список и настройки — в `%APPDATA%\MagmPaper\wallpapers.json`. При первом запуске переносится коллекция из `%APPDATA%\magmpaper-engine`, если в новой папке ещё нет библиотеки. Исходный файл сохраняется.
- Если автозапуск уже был настроен, установщик обновит его путь. Для новой установки он выключен; включается в параметрах приложения.
- Для обновления закройте приложение через трей и запустите новый установщик. Данные сохраняются.
- Удаление: «Параметры Windows → Приложения → Установленные приложения → MagmPaper». Программа, ярлыки и её запись автозапуска удаляются, коллекция остаётся в AppData.

Установщик пока без цифровой подписи, поэтому Windows может показать предупреждение о неизвестном издателе.

## Запуск из исходников и IDE

Скачайте **Visual Studio Code** (https://code.visualstudio.com/) и **Node.js 24 LTS** (https://nodejs.org/). Для обоев и интерфейса полная Visual Studio не нужна. Для сборки собственного модуля панели установите Visual Studio Build Tools с компонентами Desktop development with C++, Windows SDK и CMake.

Откройте папку проекта в VS Code. В меню «Терминал → Создать терминал» выполните:

```powershell
npm ci
npm start
```

Команды выполняются из папки с `package.json`. Если PowerShell блокирует `npm.ps1`, используйте `npm.cmd ci` и `npm.cmd start` или терминал Command Prompt; менять политику выполнения не нужно.

Для встроенного модуля и установщика (Windows x64):

```powershell
npm run build:native
npm run dist
```

Результат — `dist/MagmPaper-Setup-0.3.0.exe`. Установщик пока без цифровой подписи: Windows может показать предупреждение об неизвестном издателе. Для готового установщика Node.js и IDE не требуются.

Для ZIP-версии выполните `npm run dist:zip`. Полностью распакуйте архив в отдельную папку и запустите `MagmPaper.exe`; остальные файлы рядом с ним обязательны.

## Как пользоваться

1. Перейдите в раздел **«Обои»**. Откройте шейдер на glslsandbox.com и скопируйте **весь код фрагментного шейдера** из редактора сайта.
2. Нажмите «Добавить обои», задайте название и вставьте код.
3. Нажмите «Проверить»: ошибки компиляции появятся под редактором. После проверки нажмите «Сохранить».
4. Выберите обои в коллекции и нажмите «На рабочий стол». Значки рабочего стола остаются доступными.
5. В меню «Параметры» чекбокс «Реакция на мышь» включает или выключает взаимодействие на рабочем столе без перезапуска обоев. Настройка сохраняется между запусками; при выключении `mouse` фиксируется в центре (0.5, 0.5). Предпросмотр остаётся интерактивным.
6. Кнопка «Остановить обои» возвращает обычный фон Windows. Удаление активных обоев тоже останавливает их.

Закрытие окна сворачивает приложение в трей. Двойной щелчок по значку открывает приложение на последнем выбранном разделе. Для полного завершения выберите «Выход» в контекстном меню трея. При следующем запуске приложения последние выбранные обои восстанавливаются. В «Параметрах» включите «Запускать с Windows»: при входе в систему приложение запустится в трее и восстановит последние установленные обои. Если Проводник ещё загружается, приложение подождёт его готовности. Кнопка «Остановить обои» очищает выбор для следующего запуска.

Автозапуск работает и при разработке через `npm start`. Он привязывается к текущему пути приложения: после переноса проекта или ZIP-сборки выключите и снова включите переключатель из нового расположения.

Данные во всех вариантах запуска: `%APPDATA%/MagmPaper`. Для резервной копии скопируйте всю папку, включая `wallpapers.json` и `Wallpapers`. Приложение сохраняет изменения атомарной заменой файла; повреждённая библиотека не перезаписывается. Ошибка открытия показывает точный путь.

## Разделы и панель задач

Постоянное меню содержит «Обзор», «Обои», «Панель задач» и общие «Параметры». Новые возможности персонализации можно добавлять отдельными разделами. При переходах сохраняется черновик редактора и последний открытый раздел.

В **«Панели задач»** доступны две группы:

- **Поведение панели Windows**: расположение кнопок, поиск, кнопка представления задач, автоматическое скрытие. Эти параметры сохраняются в Windows и действуют после выхода из MagmPaper. Изменяются только выбранные пункты; отказ одного не отменяет остальные. Некоторые изменения требуют повторного входа в Windows. Кнопка «Вернуть исходные» восстанавливает сохранённые значения по отдельности.
- **Оформление панели MagmPaper**: высота панели, размер значков приложений, ширина кнопок, цвет и непрозрачность фона, скругление фона и скрытие кнопки виджетов. Включите оформление и нажмите «Применить оформление». Размеры указаны до масштабирования Windows. Доступны три готовых набора размеров.

Стандартная панель Windows сохраняется: трей, закреплённые приложения и системные меню остаются на своих местах. Модуль не заменяет её собственной панелью. Он не меняет системный выбор доступности виджетов: скрывается только кнопка на панели. Для включения самой функции виджетов используйте «Открыть параметры Windows».

Оформление действует, пока MagmPaper работает, включая режим в трее. При полном выходе или завершении помощника возвращаются исходные значения; сохранённое оформление возобновляется при следующем запуске приложения. Для постоянного запуска включите автозапуск в общих параметрах. «Вернуть оформление Windows» отключает оформление, сохраняя настройки поведения Windows. Установщик обновляет программу с сохранением обоев и файла `taskbar-appearance.json`.

Windhawk для нового модуля не нужен. Если у вас уже включены его моды **Taskbar height and icon size** или **Windows 11 Taskbar Styler**, сначала отключите их, чтобы два приложения не меняли одни и те же элементы. Прежний раздел Windhawk появляется только при найденном моде или наличии резервной копии его настроек и позволяет вернуть старые значения.

Модуль использует события создания элементов и изменения свойств, без постоянного опроса панели и отрисовки отдельного окна. Короткие таймеры нужны только для подключения и подтверждения команд. Он загружается только после включения оформления. При неподдерживаемой XAML-панели включение завершается ошибкой без сохранения ложного успеха; обои продолжают работать. Совместимость с внутренним устройством Explorer может измениться после обновления Windows.

Скрытый предпросмотр обоев приостанавливается; рабочий стол следует настройкам FPS, качества и автоматической паузы.

## Папка обоев

Кнопка со значком папки **«Папка обоев»** находится под коллекцией в разделе «Обои» и доступна в трее. Она открывает `%APPDATA%\MagmPaper\Wallpapers` в Проводнике.

- Каждым обоям соответствует `Название.glsl`, содержащий только исходный GLSL-код. При переименовании и удалении из приложения меняется соответствующий файл.
- Запрещённые в Windows символы заменяются подчёркиваниями; одинаковые названия получают суффиксы `(2)`, `(3)` и т. д.
- Можно редактировать файлы внешним редактором или положить в папку новые `.glsl`. Нажмите «Обновить коллекцию» или вернитесь в окно приложения. Несохранённый текст во встроенном редакторе не перезаписывается.
- Внешнее переименование файла считается удалением прежних обоев и добавлением новых. Если они были активными, выберите и установите их снова. Изменение кода применяйте кнопкой «На рабочий стол».
- При первом запуске после обновления старая коллекция автоматически переносится в файлы. Исходный JSON остаётся рядом как `wallpapers.json.v1-backup`. Сохраняются ID, настройки и выбранные обои. Журнал сохранения позволяет восстановить незавершённую запись после сбоя.

При переходе из полноэкранной игры приложение обрабатывает серии смен разрешения/DPI и автоматически восстанавливает WebGL после сброса драйвера. Если контекст не восстановился за несколько секунд, окно обоев пересоздаётся с ограниченным числом повторов. Win+D возвращает анимацию, даже когда игра оставила старые полноэкранные границы окна. После восстановления GPU накопленный backbuffer и время анимации могут начаться заново.

## Параметры и экономия ресурсов

Кнопка «Параметры» находится в боковом меню; пункт также есть в меню значка в трее. Изменения применяются сразу и сохраняются.

- Автозапуск и реакция на мышь перенесены в общие параметры.
- «Пауза, когда рабочий стол закрыт окном» включена по умолчанию. На паузе нет запросов новых кадров и опроса мыши; остаются лёгкие проверки состояния окна. Программа и память GPU сохраняются для быстрого возобновления.
- «Пауза при работе от батареи» включается по желанию; подключение питания возобновляет анимацию, если нет других причин паузы. При блокировке Windows обои всегда приостанавливаются.
- Частота кадров: 15 / 30 / 60 FPS. Для экономии попробуйте 30 FPS.
- Качество рендера: 50 / 75 / 100% по каждой стороне. 50% означает четверть пикселей, но менее чёткое изображение. Окно продолжает занимать весь монитор. Изменение качества сбрасывает накопленный backbuffer.
- Эти параметры относятся к рабочему столу. Предпросмотр остаётся 60 FPS и приостанавливается при открытых параметрах или скрытом окне.
- Причина автоматической паузы отображается под предпросмотром. Ручная кнопка «Остановить обои» по-прежнему полностью отключает обои и очищает выбор для автозапуска.

## Совместимость и ограничения

- WebGL 1 / GLSL ES 1.00: `time` — секунды, `resolution` — размер рендера в пикселях, `mouse` — координаты 0…1, `backbuffer` — предыдущий кадр. Есть `varying vec2 surfacePosition` в диапазоне −1…1.
- Мышь интерактивна и в предпросмотре, и на рабочем столе. Курсор опрашивается каждые 8 мс, а координаты на рабочем столе сглаживаются с постоянной времени 20 мс: (0, 0) — нижний левый угол, (1, 1) — верхний правый. Координаты вычисляются относительно основного монитора с учётом масштаба Windows. На другом мониторе координаты ограничиваются ближайшим краем. Клики проходят к значкам; отслеживается только положение курсора, в том числе поверх других окон. Шейдер должен использовать `uniform vec2 mouse`, иначе его изображение не изменится от движения мыши. Встроенный пример «Северное сияние» использует только время и сам по себе на мышь не реагирует.
- Поддерживаются самодостаточные фрагментные шейдеры без внешних текстур. Shadertoy `mainImage`, GLSL 300, внешние изображения/звук и дополнительные проходы требуют адаптации. Ссылки не импортируются: вставляйте именно код.
- Основной монитор, до 60 FPS (зависит от монитора, GPU и сложности шейдера), ограничение размеров текстур до 3840 пикселей по каждой оси; сложные шейдеры могут сильно нагружать GPU.
- Обои подключаются к слою Explorer WorkerW через Win32 API. Этот механизм не документирован Microsoft и может измениться после обновления Windows. После пересоздания слоя Explorer приложение автоматически пробует восстановить обои; при длительной ошибке доступен ручной повтор через «На рабочий стол».
- Шейдеры без активного `backbuffer` рисуются сразу на экран без дополнительного копирования кадра. Для шейдеров с `backbuffer` сохраняется накопление предыдущего кадра.
- Предпросмотр при скрытом окне приостанавливается. При сне обои освобождаются и восстанавливаются после пробуждения. При перекрытии основного монитора одним видимым полноэкранным или развёрнутым окном обои по умолчанию ставятся на паузу. Свёрнутые окна, окна других виртуальных рабочих столов, панель задач, служебные и прозрачные окна, сами обои и рабочий стол исключаются. Окна под поднятым рабочим столом (Win+D) также не вызывают паузу. Проверка выполняется раз в секунду; после закрытия или сворачивания окна анимация продолжится без скачка времени. Суммарное перекрытие несколькими маленькими окнами не определяется.
- Renderer изолирован: без Node.js, без сетевого доступа через CSP. Код пользователя передаётся только компилятору GLSL; JavaScript из него не исполняется.

## Проверки

```powershell
npm test
```

Автотесты проверяют сохранение/редактирование/выбор/удаление, восстановление библиотеки, некорректные данные и сбой записи. Проверка реального рабочего стола требует Windows 11 и GPU-драйвера:

- Установить встроенный пример; убедиться, что анимация **за значками**, значки открываются, а в Alt+Tab нет окна обоев.
- Добавить шейдер с glslsandbox.com, проверить ошибку GLSL, сохранить исправленный код и переключить обои.
- Закрыть/открыть окно через трей; проверить остановку, удаление активных обоев и сохранность коллекции после полного выхода.
- Проверить основной монитор с масштабом 100%/150%, сон/пробуждение и перезапуск Explorer.

`npm run test:windows` проверяет реальное окно Electron (размеры клиентской области и начало координат) и включение/выключение автозапуска с отдельной временной записью реестра, а также передачу реального положения курсора в изолированный рендерер при включённом пропуске кликов. Это не заменяет проверку реального Explorer после входа в Windows.

Linux подходит для тестов библиотеки и WebGL-предпросмотра. Интеграция WorkerW на Linux недоступна; успешная сборка не заменяет проверку Windows.

Тесты панели задач проверяют валидацию, возврат исходных значений и ошибки записи; на Windows — реальный API скрытия, чтение реестра и PowerShell-транзакцию в изолированной тестовой ветке. Отдельный тест C++ проверяет реальные XAML-элементы Windows: размеры, цвет, прозрачность, восстановление значений, подключение DLL, аварийное завершение помощника и повторное подключение. Это изолированное окно с тем же кодом компонента, а не настоящая панель Explorer; внешний вид, несколько мониторов, автоскрытие и работу меню необходимо дополнительно проверить на целевой сборке Windows 11.

Дополнительная проверка интерфейса: `npm run test:ui`. Нужен Chromium; путь задаётся переменной `CHROMIUM_PATH` (по умолчанию `/usr/bin/chromium`). Тест проверяет реальные пиксели WebGL, накопление `backbuffer`, ошибки GLSL и действия с библиотекой. Win32-вызовы в этом тесте не выполняются.

Полная сборка установщика выполняется на Windows x64: `npm ci`, `npm run build:native`, затем `npm run dist`. Сборка проверяет наличие собственного DLL-модуля и помощника и не создаёт неполный установщик. Тестовые компоненты в установщик не включаются.

Проверка установщика в Windows CI: `./test/installer.ps1`. На одноразовом runner проверяются установка, комплектность, ярлыки, запуск установленного приложения, перенос коллекции, повторная установка, перенос автозапуска и удаление с сохранением данных. Скрипт предназначен только для CI.
