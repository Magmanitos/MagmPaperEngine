# MagmPaper

Нативное приложение для персонализации **Windows 11 x64** на **C# / WPF / .NET 10 LTS**: живые GLSL-обои и настройка панели задач. Добавляйте фрагментные шейдеры с glslsandbox.com, сохраняйте их в коллекцию и устанавливайте на основной монитор. Есть встроенный пример, предпросмотр, редактирование, удаление, остановка и значок в трее.

## Установка и запуск

Скачайте **MagmPaper-Setup-0.4.4.exe** из [релиза 0.4.4](https://github.com/Magmanitos/MagmPaperEngine/releases/tag/v0.4.4), полностью закройте прежнюю версию через трей → «Выход» и запустите установщик.

- По умолчанию программа устанавливается для текущего пользователя в `%LOCALAPPDATA%\Programs\MagmPaper`. Папку можно выбрать в мастере установки.
- Приложение, среда .NET, ANGLE и нативные модули Windows включены в установщик. Интерфейс WPF не использует Chromium, Electron или WebView. Собственный модуль оформления стандартной панели задач также входит в комплект; Windhawk не нужен. Устанавливать Node.js, npm или VS Code не требуется. Интернет во время установки не нужен.
- Запускайте **MagmPaper** через ярлык на рабочем столе или в меню «Пуск».
- GLSL-файлы находятся в `%APPDATA%\MagmPaper\Wallpapers`, список и настройки — в `%APPDATA%\MagmPaper\wallpapers.json`. При первом запуске переносится коллекция из `%APPDATA%\magmpaper-engine`, если в новой папке ещё нет библиотеки. Исходный файл сохраняется.
- Если автозапуск уже был настроен, установщик обновит его путь. Для новой установки он выключен; включается в параметрах приложения.
- Для обновления закройте приложение через трей и запустите новый установщик. Данные сохраняются.
- Удаление: «Параметры Windows → Приложения → Установленные приложения → MagmPaper». Программа, ярлыки и её запись автозапуска удаляются, коллекция остаётся в AppData.

Установщик пока без цифровой подписи, поэтому Windows может показать предупреждение о неизвестном издателе.

## Запуск из исходников и IDE

Установите **.NET SDK 10** и откройте репозиторий в VS Code (с расширением C#) или Visual Studio с поддержкой .NET 10. Приложение запускается только в Windows; Node.js и npm больше не используются. Если в локальном проекте были свои изменения, сохраните их коммитом или через `git stash` до обновления.

```powershell
git checkout main
git pull --ff-only origin main
dotnet run --project desktop/MagmPaper/MagmPaper.csproj
```

Полностью закройте установленную версию через трей перед запуском из исходников: обе используют одну коллекцию. Редактируйте интерфейс в `desktop/MagmPaper/MainWindow.xaml`, общие стили — в `desktop/MagmPaper/Views/Theme.xaml`, обработчики — в файлах `.cs`.

Для собственной сборки модуля панели нужны Visual Studio Build Tools: Desktop development with C++, Windows SDK и CMake. Для упаковки нужен **NSIS 3**, для скриптов — **PowerShell 7**. Из корня репозитория:

```powershell
pwsh -File scripts/build-taskbar.ps1
dotnet publish desktop/MagmPaper/MagmPaper.csproj -c Release -r win-x64 --self-contained true -o artifacts/native
pwsh -File scripts/package-native.ps1
```

Результат: `dist/MagmPaper-Setup-0.4.4.exe` и `dist/MagmPaper-0.4.4-win.zip`. Установка SDK на компьютер пользователя не требуется. ZIP нужно полностью распаковать в отдельную папку; файлы рядом с `MagmPaper.exe` обязательны. Упаковка проверяет наличие собственного модуля панели и ANGLE, а также отсутствие Electron.

## Устройство нативной версии

- `desktop/MagmPaper` — окно WPF, Win32-интеграция, трей и управление обоями. XAML позволяет менять структуру, шаблоны элементов и стили без браузера.
- `desktop/MagmPaper.Core` — коллекция, транзакции файлов, совместимость форматов, параметры и расчёты поведения.
- `desktop/MagmPaper/Graphics` — отдельные потоки OpenGL ES 2.0 через ANGLE / Direct3D 11. Существующий GLSL остаётся GLSL, переписывать обои на другой язык не нужно.
- `native/taskbar` — собственный C++-модуль стандартной панели Windows и его тестовый стенд. Этот модуль уже был нативным и сохранён.
- `desktop/MagmPaper.Tests` — автономные проверки коллекции и миграции.

Пауза блокирует поток рендера без рисования кадров и опроса курсора. Для ограничения FPS используются ожидания таймера Windows. Обработка курсора выполняется вместе с кадром; отдельного постоянно работающего опросчика нет. Прямой вывод используется без backbuffer и понижения качества; в остальных случаях используются GPU-текстуры. Сброс видеоустройства согласован между предпросмотром и обоями, включая приостановленные поверхности.

При первом нативном запуске сохраняется `wallpapers.json.electron-backup`. Коллекция v1 дополнительно сохраняется как `.v1-backup`; существующие файлы v2, параметры оформления и резервные значения панели совместимы. Установщик сначала удаляет прежние программные файлы, сохраняет AppData и переносит существующий автозапуск. Удаление приложения также оставляет коллекцию. Код прежней Electron-версии доступен в [теге v0.3.1](https://github.com/Magmanitos/MagmPaperEngine/tree/v0.3.1).

## Как пользоваться

1. Перейдите в раздел **«Обои»**. Откройте шейдер на glslsandbox.com и скопируйте **весь код фрагментного шейдера** из редактора сайта.
2. Нажмите «Добавить обои», задайте название и вставьте код.
3. Нажмите «Проверить»: ошибки компиляции появятся под редактором. После проверки нажмите «Сохранить».
4. Выберите обои в коллекции и нажмите «На рабочий стол». Значки рабочего стола остаются доступными.
5. В меню «Параметры» чекбокс «Реакция на мышь» включает или выключает взаимодействие на рабочем столе без перезапуска обоев. Настройка сохраняется между запусками; при выключении `mouse` фиксируется в центре (0.5, 0.5). Предпросмотр остаётся интерактивным.
6. Кнопка «Остановить обои» возвращает обычный фон Windows. Удаление активных обоев тоже останавливает их.

Закрытие окна сворачивает приложение в трей. Двойной щелчок по значку открывает приложение на последнем выбранном разделе. Для полного завершения выберите «Выход» в контекстном меню трея. При следующем запуске приложения последние выбранные обои восстанавливаются. В «Параметрах» включите «Запускать с Windows»: при входе в систему приложение запустится в трее и восстановит последние установленные обои. Если Проводник ещё загружается, приложение подождёт его готовности. Кнопка «Остановить обои» очищает выбор для следующего запуска.

Автозапуск работает и при запуске собранного `MagmPaper.exe` из исходников. Он привязывается к текущему пути приложения: после переноса проекта или ZIP-сборки выключите и снова включите переключатель из нового расположения.

Данные во всех вариантах запуска: `%APPDATA%/MagmPaper`. Для резервной копии скопируйте всю папку, включая `wallpapers.json` и `Wallpapers`. Приложение сохраняет изменения атомарной заменой файла; повреждённая библиотека не перезаписывается.

## Разделы и панель задач

Постоянное меню содержит «Обзор», «Обои», «Панель задач» и общие «Параметры». Новые возможности персонализации можно добавлять отдельными разделами. При переходах сохраняется черновик редактора и последний открытый раздел.

В **«Панели задач»** доступны две группы:

- **Поведение панели Windows**: расположение кнопок, поиск, кнопка представления задач, автоматическое скрытие. Эти параметры сохраняются в Windows и действуют после выхода из MagmPaper. Изменяются только выбранные пункты; отказ одного не отменяет остальные. Некоторые изменения требуют повторного входа в Windows. Кнопка «Вернуть исходные» восстанавливает сохранённые значения по отдельности.
- **Оформление панели MagmPaper**: высота панели, размер значков приложений, ширина кнопок, цвет и непрозрачность фона, скругление фона и скрытие кнопки виджетов. Включите оформление и нажмите «Применить оформление». Размеры указаны до масштабирования Windows. Доступны три готовых набора размеров.

Стандартная панель Windows сохраняется: трей, закреплённые приложения и системные меню остаются на своих местах. Модуль не заменяет её собственной панелью. Он не меняет системный выбор доступности виджетов: скрывается только кнопка на панели. Для включения самой функции виджетов используйте «Открыть параметры Windows».

Оформление действует, пока MagmPaper работает, включая режим в трее. При полном выходе или завершении помощника возвращаются исходные значения; сохранённое оформление возобновляется при следующем запуске приложения. Для постоянного запуска включите автозапуск в общих параметрах. «Вернуть оформление Windows» отключает оформление, сохраняя настройки поведения Windows. Установщик обновляет программу с сохранением обоев и файла `taskbar-appearance.json`.

Windhawk для нового модуля не нужен. Если у вас уже включены его моды **Taskbar height and icon size** или **Windows 11 Taskbar Styler**, сначала отключите их, чтобы два приложения не меняли одни и те же элементы. Прежний раздел Windhawk появляется только при найденном моде или наличии резервной копии его настроек и позволяет вернуть старые значения.

Модуль использует события создания элементов и изменения свойств, без постоянного опроса панели и отрисовки отдельного окна. Короткие таймеры нужны только для подключения и подтверждения команд. Он загружается только после включения оформления. При неподдерживаемой XAML-панели включение завершается ошибкой без сохранения ложного успеха; обои продолжают работать. Совместимость с внутренним устройством Explorer может измениться после обновления Windows.

Скрытый предпросмотр обоев приостанавливается; рабочий стол следует настройкам FPS, качества и автоматической паузы.

## Папка обоев

Кнопка со значком папки **«Папка обоев»** находится под коллекцией в разделе «Обои» и доступна в трее. Она открывает `%APPDATA%\MagmPaper\Wallpapers` в Проводнике.

- Каждым обоям соответствует `Название.glsl`, содержащий только исходный GLSL-код. При переименовании и удалении из приложения меняется соответствующий файл.
- Запрещённые в Windows символы заменяются подчёркиваниями; одинаковые названия получают суффиксы `(2)`, `(3)` и т. д.
- Можно редактировать файлы внешним редактором или положить в папку новые `.glsl`. Нажмите «Обновить коллекцию» или вернитесь в окно приложения. Несохранённый текст во встроенном редакторе не перезаписывается.
- Внешнее переименование файла считается удалением прежних обоев и добавлением новых. Если они были активными, выберите и установите их снова. Изменение кода применяйте кнопкой «На рабочий стол».
- При первом запуске после обновления старая коллекция автоматически переносится в файлы. Исходный JSON остаётся рядом как `wallpapers.json.v1-backup`. Сохраняются ID, настройки и выбранные обои. Журнал сохранения позволяет восстановить незавершённую запись после сбоя.

При переходе из полноэкранной игры приложение обрабатывает серии смен разрешения/DPI и автоматически восстанавливает GPU-рендерер после сброса драйвера. Если контекст не восстановился за несколько секунд, окно обоев пересоздаётся с ограниченным числом повторов. Win+D возвращает анимацию, даже когда игра оставила старые полноэкранные границы окна. После восстановления GPU накопленный backbuffer и время анимации могут начаться заново.

## Параметры и экономия ресурсов

Кнопка «Параметры» находится в боковом меню; пункт также есть в меню значка в трее. Изменения применяются сразу и сохраняются.

- Автозапуск и реакция на мышь перенесены в общие параметры.
- «Пауза, когда рабочий стол закрыт окном» включена по умолчанию. На паузе нет запросов новых кадров и опроса мыши; остаются лёгкие проверки состояния окна. Программа и память GPU сохраняются для быстрого возобновления.
- «Пауза при работе от батареи» включается по желанию; подключение питания возобновляет анимацию, если нет других причин паузы. При блокировке Windows обои всегда приостанавливаются.
- Частота кадров: 15 / 30 / 60 / 120 / 144 / 165 / 240 FPS либо частота основного монитора (до 360 Гц). Это не меняет частоту дисплея Windows. Для экономии используйте 30–60 FPS.
- Качество рендера: 50 / 75 / 100% по каждой стороне. 50% означает четверть пикселей, но менее чёткое изображение. Окно продолжает занимать весь монитор. Изменение качества сбрасывает накопленный backbuffer.
- Эти параметры относятся к рабочему столу. Предпросмотр следует частоте основного монитора и приостанавливается, когда скрыт, полностью прокручен за край области или открыта другая страница. Его нативное окно обрезается по границам прокрутки.
- Причина автоматической паузы отображается под предпросмотром. Ручная кнопка «Остановить обои» по-прежнему полностью отключает обои и очищает выбор для автозапуска.

## Совместимость и ограничения

- OpenGL ES 2.0 / GLSL ES 1.00 (совместимые с прежним WebGL 1 шейдеры): `time` — секунды, `resolution` — размер рендера в пикселях, `mouse` — координаты 0…1, `backbuffer` — предыдущий кадр. Есть `varying vec2 surfacePosition` в диапазоне −1…1.
- Мышь интерактивна и в предпросмотре, и на рабочем столе. Курсор опрашивается при отрисовке кадра, а координаты на рабочем столе сглаживаются с постоянной времени 20 мс: (0, 0) — нижний левый угол, (1, 1) — верхний правый. Координаты вычисляются относительно основного монитора с учётом масштаба Windows. На другом мониторе координаты ограничиваются ближайшим краем. Клики проходят к значкам; отслеживается только положение курсора, в том числе поверх других окон. Шейдер должен использовать `uniform vec2 mouse`, иначе его изображение не изменится от движения мыши. Встроенный пример «Северное сияние» использует только время и сам по себе на мышь не реагирует.
- Поддерживаются самодостаточные фрагментные шейдеры без внешних текстур. Shadertoy `mainImage`, GLSL 300, внешние изображения/звук и дополнительные проходы требуют адаптации. Ссылки не импортируются: вставляйте именно код.
- Основной монитор, до 240 FPS вручную или до 360 FPS в режиме частоты монитора (зависит от монитора, GPU и сложности шейдера), ограничение размеров текстур до 3840 пикселей по каждой оси; сложные шейдеры могут сильно нагружать GPU.
- Обои подключаются через Win32 API: к WorkerW в классическом рабочем столе или отдельным непрозрачным layered-окном между SHELLDLL_DefView и WorkerW в новом рабочем столе Windows 11 24H2/HDR. Такая поверхность остаётся в композиции DWM; настройки NVIDIA/G-SYNC, частота дисплея и системный курсор не изменяются. Этот механизм не документирован Microsoft и может измениться после обновления Windows. После пересоздания слоя Explorer приложение автоматически пробует восстановить обои; при длительной ошибке доступен ручной повтор через «На рабочий стол».
- Шейдеры без активного `backbuffer` рисуются сразу на экран без дополнительного копирования кадра. Для шейдеров с `backbuffer` сохраняется накопление предыдущего кадра.
- Предпросмотр при скрытом окне приостанавливается. При сне обои освобождаются и восстанавливаются после пробуждения. При перекрытии основного монитора одним видимым полноэкранным или развёрнутым окном обои по умолчанию ставятся на паузу. Свёрнутые окна, окна других виртуальных рабочих столов, панель задач, служебные и прозрачные окна, сами обои и рабочий стол исключаются. Окна под поднятым рабочим столом (Win+D) также не вызывают паузу. Проверка выполняется раз в секунду; после закрытия или сворачивания окна анимация продолжится без скачка времени. Суммарное перекрытие несколькими маленькими окнами не определяется.
- В коде обоев нет JavaScript или доступа к файловым API: текст передаётся компилятору GLSL. Рендерер работает в процессе приложения; отдельной браузерной песочницы больше нет.

## Проверки

```powershell
dotnet run --project desktop/MagmPaper.Tests/MagmPaper.Tests.csproj -c Release
pwsh -File scripts/build-taskbar.ps1
dotnet publish desktop/MagmPaper/MagmPaper.csproj -c Release -r win-x64 --self-contained true -o artifacts/native
pwsh -File scripts/smoke-native.ps1
```

Первые тесты выполняются также на Linux: CRUD, выбор и настройки, v1/v2, чистый GLSL, внешние изменения, конфликты, восстановление журнала, повреждённые данные и миграция старой папки. WPF можно скомпилировать на Linux, запуск требует Windows.

Windows-тест запускает настоящий WPF-интерфейс и ANGLE с D3D11 WARP (программный GPU для CI), читает реальные пиксели, проверяет ошибку шейдера, backbuffer, качество, паузу, геометрию окна, курсор, восстановление устройства и действия редактора. Отчёт и снимок интерфейса находятся в `artifacts/smoke`; измерения памяти и простоя относятся только к тестовой машине, а не к производительности любого компьютера. Флаг `--smoke-test` использует отдельную временную коллекцию и не включает оформление настоящего Explorer.

C++-тесты проверяют реальные XAML-элементы в изолированном окне: размеры, цвет, прозрачность, откат, подключение DLL, аварийное завершение и повторное подключение помощника. Это не сама панель Explorer. Вид панели, меню, автоскрытие и несколько мониторов проверяются дополнительно на целевой сборке Windows 11.

`pwsh -File scripts/test-native-installer.ps1` запускается **только на одноразовом GitHub Actions runner**: устанавливает опубликованную Electron-версию 0.3.1, обновляет её нативной, проверяет данные, настройки, ярлыки, автозапуск, реальный запуск WPF/GLSL, повторную установку и удаление с сохранением коллекции и посторонних файлов.

Перед выпуском на целевом ПК дополнительно проверьте: обои за значками, масштаб 100%/150%, Win+D после игры с другим разрешением, сон/пробуждение и перезапуск Explorer. Изолированные тесты Windows не воспроизводят конкретный драйвер видеокарты и все варианты полноэкранных игр.

## Исправления 0.4.3

Тёмные выпадающие списки и полосы прокрутки, плавная прокрутка с учётом настройки анимации Windows, встроенный HSV/HEX-выбор цвета. Поздние `#extension` в GLSL Sandbox переносятся в начало шейдера только при компиляции: исходные файлы не переписываются, номера строк сохраняются. Условные директивы с пользовательскими макросами не переставляются.

Модуль панели запоминает размеры, которые Explorer задаёт после появления/повторного использования значка, и восстанавливает их при отключении и выходе. Перед восстановлением всех элементов снимаются обработчики переопределения; помощник ждёт завершения очистки в потоках панели.

Для разбора проблем есть кнопка «Скопировать диагностику» в параметрах: версия ОС, частота монитора, GPU-рендерер, состояние слоя и паузы. Код и названия обоев в отчёт не попадают. Проверки на Windows используют D3D11 WARP и отдельные тестовые окна; реальный RTX 2070 Super, VRR и Explorer 24H2 на пользовательском ПК требуют проверки после установки.

## Исправления 0.4.4

Исправлено сохранение размеров значков при анимациях и повторном обнаружении одного XAML-объекта. Изменение эффективного размера анимацией больше не записывает собственное переопределение MagmPaper как исходное значение Windows; повторные диагностические ссылки используют один снимок свойств. При «Выход» из трея восстанавливаются размеры и ограничения значков, включая значки запущенных приложений, которые появились уже после включения оформления.

Размер значка ограничивается также при компоновке, чтобы большой исходный bitmap или анимация не растягивали его. Поздно назначенное имя/родитель обрабатывается короткой серией повторов только при появлении элемента; постоянного опроса нет. Регрессионные C++-тесты включают настоящий XAML Storyboard, видимые размеры bitmap, повторные ссылки и выход помощника. Сам Steam и реальный Explorer 24H2 в CI не запускаются.
